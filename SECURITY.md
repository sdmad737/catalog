# Security Policy

## Supported version

Catalog is currently pre-1.0. Security fixes are provided for the latest code on the default branch; older snapshots are not maintained as separate security release lines.

## Report a vulnerability privately

Do **not** publish vulnerability details in a normal GitHub issue, discussion, pull request, or other public channel.

Use GitHub's **Private vulnerability reporting** for this repository when the **Security → Report a vulnerability** option is available. This creates a private report visible only to the repository's security collaborators.

If that option is not available, open a public issue containing only the sentence “I need a private channel to report a security vulnerability.” Do not include technical details, proof-of-concept code, credentials, tokens, private data, or affected deployment information. A maintainer can then establish an appropriate private channel. The project does not publish a dedicated security email address, so this policy does not invent one.

Please include privately:

- the affected version or commit;
- the affected endpoint or workflow;
- clear reproduction steps;
- expected impact;
- suggested mitigation, if known.

Allow reasonable time for investigation and remediation before disclosure. Never test against an organization or deployment you do not own or have explicit authorization to assess.

## Sensitive areas

Reports involving public NFC tokens, anonymous tag responses, authentication/session tokens, role or ownership checks, invitation links, cross-organization access, attachments, borrower privacy, or database backups are especially important.
